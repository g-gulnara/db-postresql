# Информационная система «Городская библиотека»

Распределённая информационная система для автоматизации работы библиотеки. Проект объединяет реляционную базу данных с высокой доступностью, потоковую передачу изменений, аналитическое хранилище, BI-визуализацию, мониторинг инфраструктуры и REST API на Go.


## Технологический стек

**Backend:** Go, REST API

**Основная база данных:** PostgreSQL, Patroni, etcd

**Балансировка и отказоустойчивость:** HAProxy

**Потоковая обработка данных:** Apache Kafka (KRaft), Debezium, Kafka Connect

**Аналитическое хранилище и BI:** ClickHouse, Metabase

**Мониторинг:** Prometheus, Grafana

**Резервное копирование:** MinIO

## Основные возможности

- управление состоянием узлов и автоматическое переключение лидера с помощью Patroni
- etcd для хранения состояния кластера и координации выборов лидера
- HAProxy предоставляет единую точку подключения к базе данных и маршрутизирует соединения
- Debezium отслеживает изменения в PostgreSQL и передаёт события через Kafka в аналитический контур на базе ClickHouse
-  Metabase визуализирует показатели библиотеки, включая статистику по штрафам
-  Prometheus собирает метрики, а Grafana отображает состояние узлов, репликацию и информацию о DCS.
- Pumba используется для проверки поведения инфраструктуры при искусственном завершении работы контейнеров.
- MinIO храненит резервных копии
- Go REST API: отдельный сервис подключается к PostgreSQL через HAProxy и предоставляет HTTP-эндпоинты для проверки доступности сервиса и получения статистики по штрафам.

## Архитектура

### 1. Операционный контур

PostgreSQL хранит основные данные информационной системы: каталог книг, физических экземпляров, читателей, выдач, возвратов и штрафов.

Patroni управляет кластером PostgreSQL и обеспечивает автоматическое переключение лидера при соответствующих отказах. Состояние кластера и координация узлов поддерживаются через etcd.

HAProxy выступает точкой входа для подключений к PostgreSQL. Это позволяет отделить клиентов от конкретного узла базы данных и централизовать маршрутизацию подключений.

### 2. Потоковая передача изменений и аналитика

Изменения в операционной базе передаются в аналитический контур по следующей цепочке:

**PostgreSQL → Debezium / Kafka Connect → Kafka → ClickHouse → Metabase**

Debezium реализует Change Data Capture (CDC) — получение событий об изменениях данных без необходимости регулярно перечитывать всю базу целиком. Kafka используется как потоковая платформа для передачи событий, ClickHouse — как аналитическое хранилище, а Metabase — для построения отчётов и дашбордов.

Такое разделение позволяет разграничить операционную нагрузку и аналитические запросы.

### 3. Go REST API

Go-сервис предоставляет HTTP-интерфейс для доступа к агрегированной статистике по штрафам библиотеки.

Реализованы следующие эндпоинты:

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка работоспособности HTTP-сервиса |
| `GET` | `/ready` | Проверка готовности сервиса и доступности PostgreSQL |
| `GET` | `/api/v1/stats/fines` | Получение агрегированной статистики по штрафам |

Сервис использует стандартный пакет `net/http` для обработки HTTP-запросов и `pgxpool` для управления пулом соединений с PostgreSQL. Подключение выполняется через HAProxy, параметры конфигурации передаются через переменные окружения.

Ответы API возвращаются в JSON. Для запросов к базе данных используются контексты с ограничением времени выполнения.

Пример ответа `/api/v1/stats/fines`:

```json
{
  "total_fines": 806,
  "unpaid_fines": 385,
  "unpaid_amount": 104351.97
}
```

Числа в примере соответствуют результату запроса к базе на момент проверки и могут меняться вместе с данными.

### 4. Мониторинг и проверка отказоустойчивости

Prometheus собирает метрики компонентов инфраструктуры, а Grafana используется для наблюдения за состоянием кластера, ролями узлов, репликацией и DCS.

Для проверки поведения системы при отказах используется Pumba, позволяющий искусственно завершать контейнеры и наблюдать за реакцией инфраструктуры. Это помогает проверять сценарии отказа, а не только штатный запуск сервисов.

### 5. Резервное копирование

MinIO используется как объектное хранилище для резервных копий. Это выделяет хранение бэкапов в отдельный компонент инфраструктуры.

## Предметная область

Система предназначена для автоматизации работы городской библиотеки. Она охватывает ведение каталога, учёт физических экземпляров книг, управление читателями, регистрацию выдач и возвратов, а также начисление и учёт штрафов за просрочку.

### Основные сущности

- **Book** — книга как библиографическая запись каталога.
- **Author** — автор произведения.
- **Genre** — жанр книги.
- **Publisher** — издательство.
- **BookItem** — физический экземпляр книги с уникальным инвентарным номером или штрихкодом.
- **Reader** — читатель библиотеки.
- **Employee** — сотрудник, оформляющий операции.
- **Loan** — запись о выдаче экземпляра читателю.
- **Fine** — штраф, связанный с нарушением срока возврата.

### Функциональные требования

- Ведение каталога книг с указанием авторов, жанров и издательств.
- Учёт нескольких физических экземпляров одного произведения.
- Хранение данных читателей и их читательских билетов.
- Регистрация выдачи конкретного экземпляра с указанием читателя, сотрудника и срока возврата.
- Фиксация фактической даты возврата и состояния экземпляра.
- Учёт штрафов за просрочку и их статуса оплаты.

### Бизнес-правила и связи

- **Book - Author:** многие-ко-многим (`M:N`). У книги может быть несколько авторов, а один автор может написать несколько книг.
- **Book - Genre:** многие-ко-многим (`M:N`). Книга может относиться к нескольким жанрам.
- **Book - BookItem:** один-ко-многим (`1:N`). Одной записи каталога соответствуют несколько физических экземпляров.
- **BookItem — Loan:** один-ко-многим (`1:N`). Один экземпляр может участвовать в нескольких выдачах в разные периоды времени.
- **Reader — Loan:** один-ко-многим (`1:N`). Один читатель может иметь несколько выдач.
- Физический экземпляр связан с конкретным залом и стеллажом.
- Статус экземпляра отражает его состояние: в наличии, выдан, в ремонте или списан.
- При выдаче сохраняется информация о сотруднике, оформившем операцию.
- При просрочке возврата применяется предусмотренная системой логика начисления штрафа.

Справочные данные - авторы, жанры и издательства - вынесены в отдельные сущности, чтобы избежать дублирования и обеспечить целостность данных.

## Запуск

Инфраструктура проекта запускается с помощью Docker Compose.

```bash
docker compose up -d --build
```

Go REST API после запуска доступен на порту `8085` хост-машины:

```bash
curl http://localhost:8085/health
curl http://localhost:8085/ready
curl http://localhost:8085/api/v1/stats/fines
```
