# db-postresql
# Информационная система «Городская библиотека»

### PostgreSQL + Patroni + etcd + HAProxy + Kafka (KRaft) + Debezium + ClickHouse + Metabase + Prometheus + Grafana + MinIO

### Реализовано:
- Кластер PostgreSQL с автоматическим failover через Patroni
- Балансировка нагрузки через HAProxy
- Chaos Engineering: тестирование отказов через Pumba
- CDC-пайплайн: PostgreSQL - Kafka - ClickHouse - Metabase
- BI-дашборд с метриками по штрафам библиотеки в реальном времени
- Мониторинг кластера в Grafana (роли узлов, репликация, DCS)
- Бэкапы в MinIO

## 1. Предметная область

Система предназначена для автоматизации работы  библиотеки. Она охватывает учет книжного фонда, ведение базы читателей, управление выдачей книг и контроль их состояния.

---

## 2. Функциональные требования

* Учет каталога: Система должна хранить информацию о книгах, их авторах, жанрах и издательствах.
* Учет экземпляров: Библиотека может владеть несколькими физическими копиями одной и той же книги. Каждая копия должна иметь уникальный инвентарный номер.
* Учет читателей: Хранение персональных данных пользователей и информации об их читательских билетах.
* Управление выдачей: Фиксация выдачи книг читателю с указанием конкретного экземпляра и ответственного сотрудника.
* Контроль возврата: При возврате книги необходимо фиксировать фактическую дату и состояние экземпляра.
* Система штрафов: Автоматический расчет и учет штрафов за несвоевременный возврат.

---

## 3. Бизнес-правила

1. Связи в каталоге:
* Одна книга может быть написана несколькими авторами (связь «многие-ко-многим»).
* Книга может принадлежать к нескольким жанрам одновременно (связь «многие-ко-многим»).


2. Экземпляры:
* Каждый физический экземпляр привязан к конкретному залу и стеллажу.
* Экземпляры имеют строго определенные статусы (в наличии, выдан, в ремонте, списан).


3. Процесс выдачи:
* Один читатель может иметь несколько активных выдач.
* При выдаче фиксируется сотрудник, оформивший операцию.
* Если книга возвращена позже установленного срока (due_date), система должна создать запись в таблице штрафов.

### Note
* Данные об авторах, издательствах и жанрах вынесены в отдельные справочники во избежание дублирования.
* Контактная информация (телефоны, email) привязана непосредственно к сущностям читателей и сотрудников.



Основные сущности:
* Книга (Book): Центральный объект каталога.
* Автор (Author): Создатель произведения.
* Экземпляр (BookItem): Физическая копия книги с уникальным штрих-кодом.
* Читатель (Reader): Клиент библиотеки.
* Выдача (Loan): Событие передачи книги читателю.


 Связи:
* Книга — Автор: Многие-ко-многим ($M:N$). У книги может быть соавторство, а автор может написать цикл книг.
* Книга — Экземпляр: Один-ко-многим ($1:N$). У одного названия в библиотеке может быть 10 физических копий.
* Экземпляр — Выдача: Один-ко-многим ($1:N$). Конкретный экземпляр может многократно выдаваться разным людям в разное время.
* Читатель — Выдача: Один-ко-многим ($1:N$). Один читатель может брать много книг.
